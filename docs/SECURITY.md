# 安全设计

这一节可以直接提供给安全 / IT 同事评估。

一句话概括：**不监听 `0.0.0.0`、不做转发或 NAT、不出网、不解析域名、不检查更新、只依赖 Go 标准库。**

---

## 网络边界

1. **只绑定一块网卡的地址，永不使用 `0.0.0.0`**。程序有两处监听：`127.0.0.1`（仅本机 UI 使用）和一处由用户**显式选中**的网卡地址。默认只自动采纳 `169.254.x.x`；常规网段地址必须在界面上手动点「保存」才会绑定，程序不会自己把服务绑到 Wi-Fi 或内网网卡上。
2. **不转发、不桥接**。程序不做任何 IP 转发、NAT 或代理，不是路由器。内网机上的 `IPEnableRouter` 保持默认值 `0`。
3. **无网关、无 DNS**。默认场景下直连网段为 `169.254.0.0/16`（RFC 3927 链路本地地址段），不属于任何企业的网络规划。静态 IP 场景下沿用的是内网机原有的网段地址，但这条线上只连两台机器、不存在任何网关设备；Mac 侧配置时**路由器留空**，因此不会产生指向内网或互联网的默认路由。
4. **只连接用户显式配置的对端字面 IP**。v2 由后端代浏览器向对端转发文件，因此会主动建立到对端的 TCP 连接；但目标只能是 `config.json` 里保存的 IPv4 字面量——不做 DNS 解析、不接受主机名、不访问任何网关或外部服务器、不检查更新。浏览器本身只与 `127.0.0.1` 通信，不发起跨源请求。全部依赖仅 Go 标准库。
5. **软 AP 不启用 ICS**。`link/win-start-link.ps1` 只执行 `netsh wlan set/start hostednetwork`，**不配置 Internet 连接共享**。虚拟适配器被静态指定为 `169.254.1.1/16`，与内网网段无关，也不做任何 NAT 或转发。这与 Windows「移动热点」有本质区别——后者的设置界面强制绑定一个共享来源。关闭时 `win-stop-link.bat` 会执行 `mode=disallow` 彻底移除虚拟适配器，并删除防火墙规则。

## 应用层

6. **双向签名**。对端访问必须携带 `HMAC-SHA256(配对码, method + path + 时间戳)`，时间窗 ±300 秒。本机访问（`127.0.0.1` 及本机网卡地址）免签，因为不涉及网络传输。
7. **文件名净化**。服务端对文件名强制 `path.Base` 处理，剥离所有路径分隔符和控制字符，杜绝路径穿越（`../../etc/passwd` → `passwd`）。
8. **大小强校验**。声明大小与实际接收字节数不一致时，立即删除半截文件并报错，不会留下损坏文件。
9. **流式转发 / 写盘**。后端把浏览器的上传流直接转给对端，本机不落临时文件、不做整文件内存缓冲，常数内存占用。
10. **单文件上限 2 GiB，单批次上限 500 个文件**，超限直接拒绝。
11. **凭据落盘但受控**。配对码与对端列表保存在 `~/.wbdrop/config.json`，权限 `0600`；不写注册表、不上传、不随可执行文件分发。`/api/config`、`/api/send`、`/api/probe` 三个接口只允许本机 `127.0.0.1` 调用，配对码不会出现在远程响应里。

## 明确不做的事

写清楚边界比罗列优点更重要，这几条是设计取舍，不是遗漏：

- **不加密内容**。链路是明文 HTTP over TCP，HMAC-SHA256 只负责**鉴权与防篡改**（证明请求来自持有配对码的一方），**不提供机密性**。同链路上没有第三方，抓不到包；但要对抗链路级嗅探，请自行加密后再传，或用别的方案。
- **不做文件类型 / 内容审查**，不杀毒，不限制扩展名。
- **不做审计日志**。传输记录不落盘，界面上的历史只在内存里。
- **不做多用户 / 权限分级**。配对码即全部凭据，持有即等价于完整收发权限。

## 建议同时执行的对端加固

| 项 | 设置 |
|---|---|
| 直连网卡网络位置 | 公用网络（默认即是） |
| 网络发现 / 文件与打印机共享 | 在直连网卡上关闭 |
| 网络桥接 | 确认未启用（`控制面板 → 网络连接`，检查有无"网桥"） |
| Internet 连接共享 (ICS) | 确认未启用 |
| 防火墙入站规则 | 仅放行 TCP 18432，见 [SETUP.md](SETUP.md) 的防火墙一节 |
