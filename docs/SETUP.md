# 建链

WBDrop 只要求「两端 IP 可达」，不关心这条链路怎么来的。两种建链方式，应用层完全一致，选一种即可。

| 方式 | 需要硬件 | 代价 |
|---|---|---|
| 方式 A：Wi-Fi 软 AP | 无 | Mac 传输期间无法上互联网；会发射射频 |
| 方式 B：网线直连 | 一根网线 | 需要拔插网线（或加一个 USB 网卡） |

---

## 方式 A：Wi-Fi 软 AP（纯软件，不需要任何硬件）

Windows 侧把无线网卡开成一个**不带 ICS 的软 AP**，Mac 作为普通客户端连上去。这就是"华为互传"在没有硬件条件下的近似形态。

```bat
link\win-start-link.bat        :: 右键 → 以管理员身份运行
link\mac-link-up.command       :: 双击
:: ... 传输 ...
link\mac-link-down.command     :: 双击，恢复原来的 Wi-Fi
link\win-stop-link.bat         :: 用完关闭 AP
```

**前提：无线网卡驱动必须支持「承载网络」（Hosted Network）。**

在内网机上执行 `netsh wlan show drivers`，看这一行：

```
支持的承载网络  : 是        ← 可以，方式 A 可用
支持的承载网络  : 否        ← 不可用，只能走方式 B 或蓝牙
```

经验规律：

| 网卡 | 承载网络 | 说明 |
|---|---|---|
| Realtek RTL8822CE | **是** | 多数 2019–2021 年 AMD 平台的轻薄本用这颗 |
| Intel AC 9560 / AX201 / AX211 | **否** | Intel CNVi 网卡，微软弃用该 API 后移除支持 |

> `win-start-link.bat` 会自己检测并明确报告结果，不用你肉眼判断。

**这个方式的两个固有代价，必须提前知道：**

1. **Mac 只有一个无线接口。** 连上软 AP 就必须放弃当前的互联网 Wi-Fi——传输期间 Mac 断网。传完用 `mac-link-down.command` 切回去。
2. **仍然会发射射频。** SSID 固定为 `WBDrop-Link`，企业的无线入侵检测能扫到。它不共享内网、不共享互联网，但"有没有无线信号"是另一回事。

> **SSID 和密码是可改的，建议改。** 默认值写死在 `link/win-start-link.ps1` 第 5–6 行（`$SSID = "WBDrop-Link"`、`$KEY = "wbdrop2026"`）。这是本仓库公开的默认值，实际使用请换掉：
>
> - Windows 侧：直接改这两行。
> - Mac 侧：`mac-link-up.command` 已支持环境变量覆盖，无需改文件——`WBDROP_SSID=你的SSID WBDROP_PASS=你的密码 ./mac-link-up.command`。
>
> 两端改完要重新建链一次（Windows 先 `win-stop-link.bat` 再重跑 `win-start-link.bat`，Mac 重新执行 `mac-link-up.command`）。密码至少 8 位，`netsh wlan set hostednetwork` 不接受更短的值。

## 方式 B：网线直连

这条链路只用到两块**已经存在**的网卡，不需要 P2P、不需要路由器、不需要互联网。

**如果两台机器各自已经有一个带 RJ45 口的外接适配器，那么唯一缺的硬件是一根网线。**

### 现有硬件的清点

| 位置 | 需要的东西 | 常见情况 |
|---|---|---|
| 内网机 | 一个带 RJ45 口的 USB 适配器 | 已经用来接内网线，**已有** |
| Mac | 一个带 RJ45 口的 USB 适配器 | 外接扩展坞通常自带，**已有** |
| 两台之间 | **一根网线**（1–2 米 Cat5e） | 唯一需要补的 |

网线两端都支持 Auto-MDIX，**用普通直通线即可，不需要交叉线**。

### 两种接法，选一个

| 接法 | 要补的硬件 | 传输时两台机器的联网状态 | 合规视角 |
|---|---|---|---|
| **① 拔插切换**（推荐） | **一根网线**（约 5–10 元） | 内网线拔下、Mac 的互联网线也拔下：传输的十几秒里两台机器都是离线的 | 最干净。任何时刻都不存在"同时连着两个网络"的机器 |
| ② 双网口并存 | 一根网线 + **一个额外的 USB 转 RJ45**（约 40–80 元） | 内网线与 Mac 的互联网线都保持不动，直连是第二块网卡 | 需要说明直连口不做转发、内网口不因此暴露 |

**推荐 ①，理由不是省钱，而是它把风险降到了零。** 拔掉内网线之后再插直连网线，内网机在那十几秒里**物理上不存在**通向内网的路径，因此不可能发生转发。这与"用移动硬盘摆渡前先断网"是同一套逻辑，安全评审最容易通过。代价是内网机临时没有内网、Mac 临时没有互联网，而 30 MB 只需十几秒。

> ⚠️ 拔插切换的唯一纪律：**直连网线必须插在"拔掉原网线后空出来的那个口"上**。一块适配器上永远只插一根线，不要出现两张网络同时在线的状态。

> 如果某台机器的联网本来就走 Wi-Fi（而不是那根网线），那一侧就不需要拔线，只需把它空着的 RJ45 口接上直连网线。

### ① 拔插切换的操作步骤

1. 内网机：拔下适配器上的内网网线，改插直连网线
2. Mac：拔下适配器上的互联网网线，插上直连网线的另一端
3. 等 10–20 秒，两端各自获得 `169.254.x.x`（见下一节）
4. 启动 WBDrop，传输
5. 传完先关程序，再把两根网线换回原位

### 插线前先确认三件事

| 检查项 | 怎么查 | 不符合时的影响 |
|---|---|---|
| 适配器是**自动获取 IP**，不是静态 IP | Windows `ipconfig /all`，看该网卡是"DHCP 已启用: 是" | 静态 IP 的网卡插上直连不会退到 `169.254.x.x`，两端不同网段，连不通 |
| 适配器速率 | Mac「系统信息 → 网络」看该网卡的"速度"；Windows 任务管理器 → 性能 → 以太网 | 百兆也能用：约 11 MB/s，30 MB 需 3 秒 |
| 扩展坞是不是 USB 2.0 | 若扩展坞只标 USB 2.0，千兆网卡实际被压在约 35–40 MB/s | 仍然远快于需求，无需换硬件 |

> 免驱这一点很关键：内网机不需要安装任何驱动程序，绕开了"内网机装不了东西"的限制。

## 硬件选型（如果确实要买）

**两台机器已有带 RJ45 口的适配器时，这一节可以跳过。**你只需要一根网线；只有在"不想每次拔插"时才需要再买一个适配器。

需要从零配齐时，两样东西：

1. **两个 USB 转 RJ45 网卡适配器**（芯片为 RTL8153 或 AX88179 即可，Windows 10/11 与 macOS 均**免驱**，插上就能用）
2. **一根普通网线**（Cat5e 及以上，Auto-MDIX 不需要交叉线）

**推荐：USB 转 RJ45 网卡适配器，而不是 USB 对拷线。**

| 维度 | USB 转 RJ45 适配器 | USB 对拷线 |
|---|---|---|
| 系统驱动 | **免驱**（Win10/11 与 macOS 自带 RTL8153 / AX88179 驱动） | 需装厂商驱动 |
| 内网机要装东西吗 | **不用** | 要装驱动 + 配套软件 |
| 能否用 WBDrop | **能**，链路就是一块普通网卡 | **不能**，私有桥接协议，不是网卡 |
| macOS 15 兼容性 | **原生支持** | 多数产品只到 macOS 12 且需装 kext，macOS 13+ 限制严格，风险高 |
| 价格 | 千兆约 70–100 元/个；百兆约 30–40 元/个 | 约 100–200 元/根 |

对拷线的根本问题是：它靠桥接芯片 + 厂商私有协议工作，操作系统里**不会出现一块网卡**，因此任何自己写的传输程序都用不上，只能用它自带的那个软件。而内网机装第三方驱动和软件这件事本身，往往比"多买一个适配器"更难通过审批。

**选购要点：**

- 芯片认 **RTL8153**（Realtek）或 **AX88179**（ASIX），这两个在 Windows 10/11 和 macOS 上都是系统自带驱动
- 避开"驱动需要单独下载"的杂牌产品
- 只传 30 MB 级别文件，**百兆（100 Mbps，约 12 MB/s，30 MB 需 2.5 秒）已经够用**，比千兆便宜一半；要传 GB 级素材再上千兆
- 网线用普通 Cat5e 即可，1 米大约 5–10 元

**方式 B 的优势是没有射频痕迹，且 Mac 不断网。**

## 链路配置：先判断对端是 DHCP 还是静态 IP

1. 网线两端分别插到两台机器的 RJ45 口上
   - **拔插切换（①）**：先拔掉两侧原有的网络线，直连网线插在空出来的口上，一块适配器只插一根线
   - **双网口并存（②）**：内网线与 Mac 的互联网线保持原样，直连线插在额外那个适配器上

2. **先判断内网机的地址是自动获取还是手工写死。** 这一步决定后面怎么配，必须先做。

   在内网机打开命令提示符：

   ```
   ipconfig /all
   ```

   找到插着直连网线的那块以太网适配器，看这两行：

   ```
   描述 . . . . . . . . . . . . . : Realtek USB GbE Family Controller
   DHCP 已启用  . . . . . . . . . : 是
   ```

   | 结果 | 常见含义 | 后果 |
   |---|---|---|
   | `DHCP 已启用: 是` | IP 由 DHCP 服务器按 MAC 保留分配（"IP 和 MAC 绑定"多半是这种） | 拔线后拿不到 DHCP，网卡自动退到 `169.254.x.x`，**两端零配置** |
   | `DHCP 已启用: 否` | 手工写死的静态 IP | 拔线后地址**不变**，仍停在内网网段，两端不同网段，走第 4 步 |

3. **情况 A：两端自动获得 `169.254.x.x`**（对应 `DHCP 已启用: 是`）

   等待 10–20 秒后确认地址。

   Windows：

   ```
   ipconfig
   ```

   找到新出现的以太网适配器，看到这一行即可：

   ```
   自动配置 IPv4 地址 . . . . . . . : 169.254.123.45
   ```

   macOS：

   ```
   ifconfig | grep "inet 169.254"
   ```

   两端都是 `169.254.x.x/16` 就同网段了。此时 WBDrop 启动会自动选中该地址，「设置」里显示「已就绪」，直接跳到第 5 步（网卡这一步可跳过）。

4. **情况 B：内网机是手工静态 IP**（对应 `DHCP 已启用: 否`）

   Windows 拔线后**不会**退到 `169.254`——静态配置一直有效。Mac 停在 `169.254`、Windows 停在 `10.x`，两边不通。

   **处理原则：内网机的 IP、掩码、MAC 一律不动，只改 Mac 这一侧。** 两端各跑一个脚本，不需要手工挑地址、不需要去网页点「直连网卡」。

   **第一步（Windows，右键 → 以管理员身份运行）：**

   ```
   link\win-prepare-static.bat
   ```

   它会：打印该网卡**真实的 IPv4 和子网掩码**（抄下来）、放行 `18432` 入站（仅公用网络配置）、把正在运行的 WBDrop 自动绑定到这个地址、显示本机配对码。执行前会要求输入 `YES` 确认「内网线已拔、直连线已插」——如果内网线还插着，绑定到 `10.x` 就等于把服务暴露到内网，**不要在这一步说谎**。

   **第二步（Mac，把刚才抄到的两个值填进去）：**

   ```
   cd wbdrop/link
   ./mac-eth-join-static.command <Windows的IP> <子网掩码>
   ```

   > ⚠️ **参数是 Windows 的地址，不是给 Mac 配的地址。** 脚本会自动挑一个同网段空闲地址（若 Mac 上已有合适的静态地址则复用），你不需要自己想一个。
   > 例：Windows 是 `10.20.30.216 / 255.255.255.0` → `./mac-eth-join-static.command 10.20.30.216 255.255.255.0`

   **关于掩码和网关，两点容易踩：**

   - **掩码一时拿不到，先用 `255.255.255.0` 是安全兜底。** 真实掩码看 Windows `ipconfig /all` 的「子网掩码」行，或直接用 `win-prepare-static.bat` 打印的值。只要 Windows 真实掩码是 `/24`、`/23`、`/20`、`/16` 之一，而 Mac 用 `/24` 且地址与 Windows 前三段相同，双向都会判定为同网段——同网段通信靠 ARP 直连，不经过网关，掩码不完全一致也能通。
   - **Windows 的网关（如 `10.20.30.1`）绝对不要填给 Mac。** 脚本的「路由器」字段是刻意留空的。填进去会让 Mac 的默认路由指向这根直连线，互联网立刻断，流量方向也会反过来变成越界风险。拔线后 Windows 静态配置里那个网关字段仍然留着，但它已经不可达，也不参与本机到 Mac 的同网段通信，无需改动。

   脚本还会自动完成/检查四件事：

   | 动作 | 说明 |
   |---|---|
   | 修正 `/32` 掩码 | 若在系统设置里误选了「使用 DHCP（手动地址）」，macOS 会给出 `0xffffffff` 掩码；此时没有到对端的路由，包全走 Wi-Fi 默认网关。脚本用 `-setmanual` 改成正确掩码 |
   | 检测网段重叠 | 若该网段与 Mac 默认路由接口（通常是 Wi-Fi）重叠，会**拦下并要求确认**。重叠时两个接口同网段，路由会乱，且 Mac 会在连互联网的同时挂上内网地址 |
   | 自动切 WBDrop | 通过 `POST /api/config` 把直连监听器切到新地址，保留所有已保存对端，不用去网页点选 |
   | 验证默认路由 | 确认互联网仍走 Wi-Fi；若 USB 网卡抢了默认路由，给出「设定服务顺序」修复指引 |

   两端程序都要**先运行**再跑脚本；脚本检测到程序没开时会打印手动选择指引，不会静默失败。

   **第三步（传完）：** Mac 执行 `./mac-eth-back-dhcp.command` 恢复 DHCP 并自动重新绑定；Windows 先关闭 WBDrop 再插回内网线。

   > 为什么不给内网机加一个 `169.254` 副地址？那需要管理员权限，且改动了受保护机器的网卡配置。让 Mac 加入内网机所在网段，内网机侧一个字都不改——这个说法在安全评审里最容易通过。

   > ⚠️ 代价要说清：Mac 会短暂持有**一个内网网段的地址**。只要这根线两端只连这两台机器，内网侧看不到 Mac（没接交换机、没网关）。给这根线两端贴标记——不要随手插进墙上网口，那才是真正越界。

5. **两端各启动一次 WBDrop。** 情况 A 下程序会自动采纳 `169.254.x.x`；情况 B 下两个脚本已经自动完成绑定，打开网页确认「设置」里的直连地址不是空的即可。

   程序不替你猜：优先恢复上次保存的选择，否则只自动采纳 `169.254.x.x`，常规网段地址必须显式确认——这是为了避免把服务误绑到 Wi-Fi 或内网网卡上。若确实需要手选：「设置 → 直连网卡」→ 选中 → 「保存」，选一次即可，之后自动恢复。

> Windows 会把这个连接显示为**「未识别的网络」**——这是正确状态，不是故障。它确实不连接任何网络。

## Windows 端必须做的一步：放行防火墙

Windows 对"未识别的网络"套用最严格的**公用网络**防火墙策略，默认阻止所有入站连接。不放行的话，对端会一直连不上。

> 静态 IP 场景下，`link\win-prepare-static.bat` 会自动执行下面这条规则，不需要手工敲；确认规则是否已存在可用 `netsh advfirewall firewall show rule name="WBDrop"`。

**以管理员身份**打开命令提示符，执行一次即可：

```
netsh advfirewall firewall add rule name="WBDrop" dir=in action=allow protocol=TCP localport=18432 profile=public
```

删除规则（不再需要时）：

```
netsh advfirewall firewall delete rule name="WBDrop"
```

> 这条规则只放行 18432 端口，且只在公用网络配置下生效。程序本身只监听直连网卡的地址，不监听 `0.0.0.0`，因此内网网卡上不会有任何端口暴露。

> 拔插切换后，Windows 可能会弹「是否允许此电脑被其他设备发现」——一律选**否**，让该连接保持「公用网络」，上面的规则才会生效。若之前误选了"是"，到「设置 → 网络和 Internet → 以太网 → 网络配置文件」改回「公用」即可。
