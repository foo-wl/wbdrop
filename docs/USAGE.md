# 使用

程序对等：两端各运行一次、各添加一次对方，双向即可互传。没有服务端/客户端之分。

---

## 分发程序

编译产物在 `dist/` 目录：

| 文件 | 目标平台 |
|---|---|
| `wbdrop-windows-amd64.exe` | Windows 10/11 x64 |
| `wbdrop-macos-amd64` | macOS Intel（x86_64） |
| `wbdrop-macos-arm64` | macOS Apple Silicon |

用移动硬盘把 `.exe` 拷到内网机。**双击运行，无需安装**。卸载就是删除这个文件。

macOS 首次运行会被 Gatekeeper 拦截，右键点击 → 打开 → 确认打开，或执行：

```
xattr -d com.apple.quarantine ./wbdrop-macos-amd64
```

## 首次配置（每台机器一次，之后不再需要）

1. **两端各双击运行一次**，自动打开 `http://localhost:18432`。
2. **点右上角「设置」**，确认「直连网卡」不是空的。
   - 若地址以 `169.254.` 开头，程序自动选中，这一步可跳过。
   - 静态 IP 场景下 `win-prepare-static.bat` / `mac-eth-join-static.command` 已自动绑好；若仍为空，手动选一次并点「保存」。
   - 该选择会被记住，重启后自动恢复。
3. **记下「本机配对码」**（设置面板顶部），告诉对方。
4. **在「添加对端」里填三样**：别名（随便起，如"内网机"）、对方的 IP、**对方的配对码**，点「保存并测试」。
   - 显示"已保存，连接正常"即完成。
   - 右上角状态灯变绿显示「已连接 · 内网机」。
   - 支持保存多个对端，用顶部下拉框切换，切换结果也会记住。

> 两端都要各自添加一次对方，双向才能互传。程序完全对等，没有服务端/客户端之分。

## 日常使用

**把文件拖进浏览器窗口任意位置，松手即发。** 没有「开始发送」按钮，没有队列确认，没有每次输入 IP。可一次拖多个文件，串行发送，逐个显示进度、耗时和速率。失败的项目带「重试」按钮。

文件落在对端的 `~/Downloads/WBDrop/`（macOS）或 `C:\Users\<用户名>\Downloads\WBDrop\`（Windows）。「接收」卡片实时显示对方发过来的进度。

## 配置存在哪

`~/.wbdrop/config.json`（Windows 为 `C:\Users\<用户名>\.wbdrop\config.json`），权限 `0600`。内容包含：

| 字段 | 说明 |
|---|---|
| `code` | **本机**配对码。首次启动生成后固定不变，对端保存的码才不会失效 |
| `bind` | 上次选中的直连网卡地址，重启自动恢复 |
| `active` | 当前默认发送目标 |
| `peers[]` | 已保存的对端：别名、字面 IP、端口、对方配对码 |

要重置，删掉这个文件并重启程序即可。

## 命令行参数

```
wbdrop-windows-amd64.exe [选项]

  -port int        监听端口（默认 18432）
  -dir  string     接收目录（默认 ~/Downloads/WBDrop）
  -bind string     直连地址；默认沿用上次保存的，否则只自动采纳 169.254.x.x
  -code string     覆盖本机配对码（默认使用配置文件里固定的那个）
  -no-browser      启动后不自动打开浏览器
```

**关于 `-bind`**：不传时优先恢复上次保存的网卡，否则自动采纳 `169.254.x.x`；若网卡是静态 IP，控制台会显示「未选择直连地址」，此时在网页「设置 → 直连网卡」里选即可，无需重启。也可以用 `-bind` 一次性指定：

```
wbdrop-windows-amd64.exe -bind 10.20.30.40
```

地址必须属于本机某块网卡，否则程序会拒绝启动并列出所有可用地址。绑定常规网段地址时控制台会额外提示：插回内网线前先关闭程序。
